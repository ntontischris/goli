# Data plan — Σχολές, Βάσεις, ΕΒΕ, Πρόσβαση

Το σχήμα είναι στο [`db/schema.sql`](../db/schema.sql) και έχει ελεγχθεί σε PostgreSQL 16.

## 1. Βασική ιδέα του μοντέλου

```
department (σταθερό, 1 ανά τμήμα, σταθερό slug/URL)
   ├── institution, city, department_family (κοινή περιγραφή ομοειδών)
   ├── offering (ανά έτος × διαδρομή πρόσβασης)  ← κωδικός μηχανογραφικού
   │      ├── admission_result (ανά κατηγορία υποψηφίων: γενική, 10%, ...)  ← βάση, θέσεις
   │      └── coefficient (συντελεστές, Φάση 2)
   ├── ebe (ανά έτος, προαιρετικά ανά διαδρομή, κανονική ή ειδική)
   ├── special_requirement (ειδικά μαθήματα, αγωνίσματα, υγειονομικά, ύψος, ΠΚΕ)
   └── transfer_membership / transfer_non_equivalent (ανά εγκύκλιο)

κάθε ετήσια τιμή ──▶ source_record (url, publisher, έτος, verified_at)
κάθε import      ──▶ ops.import_batch (hash αρχείου, report, status)
```

- **Σταθερό και ετήσιο είναι ξεχωριστά.** Η καρτέλα `/sxoles/{slug}` δεν αλλάζει URL από χρονιά σε χρονιά. Τα έτη είναι γραμμές, όχι στήλες (δεν υπάρχει `base_2025` / `base_2026`).
- **Πολλές διαδρομές πρόσβασης:** ένα τμήμα έχει πολλά `offering` το ίδιο έτος (π.χ. ΓΕΛ πεδίο 2, ΓΕΛ πεδίο 4, ΕΠΑΛ τομέας). Έτσι εξηγούνται οι 766 εγγραφές ΓΕΛ που αντιστοιχούν σε 453 τμήματα.
- **Ένστολα:** σημαία `is_uniformed` και `institution.kind`. Οι ιδιαιτερότητές τους (ύψος, αγωνίσματα, ΠΚΕ) μπαίνουν ως `special_requirement`.
- **Δημοσίευση ανά έτος:** το `admission_year.status = 'published'` ελέγχει τι εμφανίζεται δημόσια. Ένα νέο έτος εισάγεται ως draft, ελέγχεται και μετά δημοσιεύεται συνολικά.
- **Συγχωνεύσεις τμημάτων:** με `status = 'merged'` και `merged_into_id`. Δημιουργείται αυτόματα 301 redirect.

## 2. Import pipeline

CLI και admin UI (upload) με τα ίδια βήματα:

1. **Parse** CSV ή XLSX με δηλωμένο mapping στηλών ανά dataset.
2. **Validate**: σχήμα, εύρος τιμών (π.χ. βάση 0–20000, συντελεστής ΕΒΕ 0.80–1.20), ύπαρξη canonical ID, διπλότυπα, υποχρεωτική πηγή και έτος. Παράγει **validation report** με errors (μπλοκάρουν) και warnings (π.χ. μεταβολή βάσης > 3000 μόρια από πέρσι).
3. **Dry-run**: diff (νέα, αλλαγμένα, αμετάβλητα) χωρίς εγγραφή.
4. **Apply** σε ένα transaction. Καταγράφεται το `import_batch_id` σε κάθε γραμμή.
5. **Rollback** ανά batch (διαγραφή ή επαναφορά των γραμμών του batch).

**Idempotency:** το ίδιο αρχείο (sha256) δεν εφαρμόζεται δύο φορές. Τα upserts γίνονται σε φυσικά κλειδιά (`department_id, admission_year, access_route_id`).
